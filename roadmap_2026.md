# WTinker — приоритетный план развития (октябрь 2026)

**Продукт:** социальная сеть для работы. Ключевой сценарий: человек ведёт смены, взаимодействует с коллегами и командами и сохраняет контроль над своими данными.

**Правила внедрения**
- Эволюционно расширять существующие возможности; не удалять/обнулять профили, расчёты, сообщения, медиа, E2E-ключи, локальные записи.
- Новая функция принимается только после прохождения TypeScript, unit/integration тестов, GitHub Actions, браузерных проверок desktop/mobile в светлой/тёмной теме. API-изменения — с миграцией и обратной совместимостью.
- Не хранить незашифрованные E2E-ключи на сервере; PIN/OnePass не считать ключами шифрования. Шифрование, миграция и восстановление — отдельные проверяемые операции.
- Без обязательного AI, маркетплейса и декоративных UI-функций. Работающие сценарии важнее количества пунктов в меню.
- Этот документ описывает **запланированное**. Отметка `[x]` означает конкретно внедрённый и проверенный инкремент, а не завершённую подсистему. Даты релизов назначаются после выполнения exit criteria.

## Очередность и зависимости

| Приоритет | Инновация | Почему именно здесь | Зависит от | Результат |
|---|---|---|---|---|
| P0 | **Secure Sync / E2E и сохранность данных** | Без уверенного переноса ключей чаты ненадёжны при смене телефона | Существующие E2E, аутентификация, IndexedDB | Зашифрованные резервные копии, доверенные устройства, перенос через подтверждение, восстановление групп |
| P0 | **Offline First 2.0** | Нельзя терять изменения при нестабильном соединении | Устойчивая модель данных, E2E | Durable outbox, идемпотентная синхронизация, конфликты, статус операций |
| P1 | **WTinker Shift** | Основной ежедневный продуктовый сценарий и отличие от обычного мессенджера | Календарь, заметки, офлайн-очередь | Журнал смены, начало/окончание, передача смены с подтверждением |
| P1 | **WTinker Teams** | Работа в сменах должна иметь явного адресата и права | Shift, роли, рабочие команды | График команды, участники, разрешения, история решений |
| P1 | **Интерактивные сообщения** | Убирает разрыв между обсуждением и действием | E2E, Shift, Teams, аудит прав | Карточка смены/задачи/опроса с подтверждением из чата |
| P1 | **WTinker Finance** | Усиливает работающие расчёты, повышает ежедневную полезность | Payroll и модель рабочих периодов | Факт/прогноз, объяснение расчёта, экспорт |
| P2 | **Профессиональный профиль 2.0** | Социальная идентичность и доверие | Приватность, роли | Опыт/навыки/портфолио, подтверждения, настройки видимости |
| P2 | **Совместное планирование времени** | Использует реальные графики команд | Shift, Teams, модель приватности | Добровольная доступность, общие выходные, предложения встреч |
| P2 | **Пространства сообществ** | Масштабирование групп без потери структуры | Команды и права, документы | Разделы, файлы, события, независимые ACL |
| P2 | **Единый центр рабочего дня** | Итоговый слой над рабочими событиями | Почти все вышеперечисленные | Персональная хронология с точными переходами и фильтрами |

## Выполнение по релизным этапам

### Этап 0 — защита основ и наблюдаемость (P0)
- [x] Сохранение исторических E2E-идентичностей в текущем коде; блокировка самопроизвольной замены ключа; защита перед PWA-обновлением (уже существовало до этого плана).
- [ ] Диагностика целостности ключей, аудируемые ошибки без логирования закрытого материала.
- [ ] Набор совместимых fixtures: старые текстовые сообщения, медиа, групповые конверты, разные версии браузера.
- [ ] Регрессионные тесты IndexedDB, WebAuthn-сессий, публикации SW, смены браузера.

**Критерий завершения:** обновления, восстановление и обычная навигация не заменяют E2E identity; ни одно зашифрованное сообщение не становится нечитаемым при сохранённых ключах.

### Этап 1 — переносимый E2E backup (P0) — первая реализация
- [x] Локальный экспорт всех доступных версий E2E-ключа в **зашифрованный файл** (AES-256-GCM, PBKDF2-SHA-256, отдельные salt/nonce, аутентификация метаданных).
- [x] Восстановление из файла только для вошедшего в аккаунт пользователя с проверкой зарегистрированного серверного публичного ключа; никаких автоматических ротаций.
- [x] Статус/ошибки/понятный UI в «Настройки → Аккаунт».
- [x] Тесты успешного round-trip, несовпадения аккаунта/ключа, неправильного пароля, повреждения файла, сохранения старых ключей.
- [x] Браузерная проверка импорта/экспорта и mobile layout.

**Критерий завершения:** пользователь может зашифровать, скачать, перенести и восстановить свой ключ, прочитать старые сообщения и файлы; сервер не получает пароль или закрытый ключ.

### Этап 2 — Secure Sync между устройствами (P0)
- [x] Связывание двух авторизованных сессий через краткоживущий QR, сверку шести цифр на обоих устройствах, двухстороннее подтверждение и зашифрованный перенос ключей.
- [ ] Постоянный список доверенных устройств, управляемый отзыв доступа, долговременный аудит событий. Краткоживущие E2E-передачи и однократное подтверждение уже реализованы.
- [ ] Согласованность групповых ключей/истории без ротации существующих индивидуальных ключей.
- [ ] Автоматические тесты race/replay/malicious peer, recovery, смены телефона.

**Критерий:** новая авторизованная сессия не получает ключ до подтверждения, после подтверждения читает историю, отключённое устройство не получает новые данные.

### Этап 3 — Offline First 2.0 (P0)
- [x] Индексированная долговечная локальная очередь зашифрованных **личных сообщений**: изоляция по аккаунту, ожидающая отправка, восстановление после перезагрузки, возврат online, отображение статуса, ручные повтор/удаление.
- [x] Уникальный clientMessageId в API личных сообщений для идемпотентности повторов; подтверждение доставки; backoff и различение сетевых/постоянных ошибок.
- [x] Локальное автосохранение черновиков редактора смен с восстановлением после перезагрузки; подтверждение сохранения до удаления черновика (PR #32).
- [x] Локальная IndexedDB-очередь зашифрованных **текстовых групповых сообщений**, с серверной идемпотентностью, повтором и ручным управлением (PR #33).
- [ ] Надёжная очередь медиа и вложений, групповых не-текстовых сообщений и изменений календаря с конфликтоустойчивой синхронизацией.
- [ ] Разрешение конфликтов рабочих записей, единая история синхронизации и уведомления о сбоях.
- [ ] Полные browser/chaos тесты всех офлайн-операций при обновлении приложения, сбоях и конфликтных изменениях.

**Критерий:** после рестарта и восстановления сети ни один офлайн-черновик не пропадает и действие не применяется дважды.

### Этап 4 — Shift и Teams (P1)
- [ ] Работа с журналом смены: события, фото, документы, чек-лист, экспорт, авторство и время.
- [ ] Передача смены: черновик → запрос → принятие/отклонение → закрытый аудит.
- [ ] Командный календарь с приватностью и RBAC (владелец/администратор/сотрудник).
- [ ] Проверки пересечений, корректные часовые пояса, мобильная эргономика.

**Критерий:** в сквозном сценарии два пользователя могут передать смену с подтверждением, прочитать связанные материалы и видеть корректные права доступа.

### Этап 5 — Interactive Messages и Finance (P1)
- [ ] Типизированные зашифрованные карточки задачи, смены, опроса и подтверждения в переписке; сервер проверяет права на действия.
- [ ] Связь карточки с актуальным объектом; нет подмены автора/владельца.
- [ ] Сравнение прогноз/факт начислений, детализация формулы, экспорт без изменения действующей логики.

**Критерий:** карточки в чате корректно связаны с Shift и Teams; существующие E2E-сообщения и финансовые тесты не ломаются.

### Этап 6 — социальные улучшения (P2)
- [ ] Расширенный профиль с разрешениями видимости и безопасной загрузкой портфолио.
- [ ] Добровольное сопоставление свободного времени коллег без утечки частных графиков.
- [ ] Структурированные пространства сообществ, документы и события с RBAC.
- [ ] Единая хронология событий с переходами в оригинальный объект и отключаемыми источниками.

**Критерий:** все новые социальные сущности проходят тесты приватности и прав, навигация/уведомления доступны на мобильном и десктопе.

## Текущий инкремент
