# WorkerTink 2.5.0

**WorkerTink** — локальный PWA для рабочего календаря, смен, зарплаты, отпусков, больничных и заметок по сменам.

Приложение работает офлайн, устанавливается как PWA и может размещаться на GitHub Pages. Основной профиль хранится локально на устройстве; backend для работы приложения не нужен.

## Возможности

### Рабочий календарь

- графики `5/2`, `4/1`, `3/2`, `3/1`, `6/1`, `2/2`, `7/0`;
- дневные и ночные смены;
- `2/2`: День/День, День/Ночь, Ночь/Ночь;
- `7/0`: День, Ночь или Сутки;
- для `7/0` задаётся непрерывный период вахты от 1 до 6 месяцев; после окончания выбранного периода календарь показывает выходной период до следующей даты начала;
- дата начала — реальная точка отсчёта цикла, без захардкоженных дат;
- даты до выхода на работу отображаются как «До начала» и не открываются для редактирования;
- ручная замена отдельной смены;
- заметки прямо на конкретной дате;
- федеральные праздники и известные переносы для поддерживаемых годов;
- настраиваемый коэффициент праздничной доплаты.

### Расчёт зарплаты

Расчётное ядро разделяет:

- плановые часы по графику;
- фактически отработанные плановые смены;
- дополнительные смены, добавленные вручную в выходной по графику;
- праздничные часы;
- ночные смены;
- отпускные;
- больничные;
- НДФЛ;
- аванс и остаток.

Для смен `День` и `Ночь` используется 8 часов, для `Сутки` — 24 часа. Ночная доплата настраивается отдельно; по умолчанию установлено 20%. Фактический размер доплаты зависит от условий работодателя.

Аванс по умолчанию равен 50% указанного оклада и может быть переопределён отдельно для любого месяца. Это модель планирования, а не утверждение о фактическом порядке выплат конкретного работодателя.

### Отпуск и больничные

- периоды отпуска и больничного хранятся отдельно;
- праздничные дни внутри ежегодного отпуска не расходуют дни отпуска;
- дни отсутствия исключаются из обычной оплаты смен;
- отпускные используют средний доход за доступную историю 12 месяцев;
- больничные используют доступную историю 24 месяцев и коэффициент по стажу: `<5` лет — 60%, `5–8` — 80%, `8+` — 100%.

Расчёты отпуска и больничного остаются пользовательской моделью и не заменяют расчёт работодателя: конкретные правила зависят от условий трудового договора, локальных актов и применимого законодательства.

### Визуальный редактор заметок

Редактор заметок работает как WYSIWYG-редактор:

- текст форматируется и отображается сразу;
- нет отдельного окна предпросмотра;
- жирный, курсив, заголовки, списки, цитаты, код и ссылки;
- создание и редактирование Markdown-таблиц;
- ПК: `Ctrl/Cmd+B`, `Ctrl/Cmd+I`, `Ctrl/Cmd+K`, `Ctrl/Cmd+Shift+7`, `Ctrl/Cmd+Shift+8`, `Ctrl/Cmd+Shift+X`;
- мобильная toolbar-панель с постоянно видимыми кнопками форматирования;
- заметка хранится как Markdown и может экспортироваться в `.md`;
- общий импорт/экспорт заметок сохраняет структуру `## SHIFT: YYYY-MM-DD`.

Markdown-адаптер является намеренно ограниченным форматом редактора: заголовки, списки, цитаты, код, ссылки, базовое inline-форматирование и таблицы. Сложный произвольный Markdown вне этого набора не гарантируется.

### Данные и восстановление

- основной профиль хранится в `localStorage`;
- формат профиля имеет версию схемы и последовательную нормализацию при загрузке;
- старые ключи `v2`/`v3` читаются автоматически;
- импорт JSON проходит через ту же нормализацию, что и обычная загрузка;
- при повреждённом профиле исходный JSON пытается сохраниться в recovery-снимок перед переходом к безопасному профилю по умолчанию;
- экспорт JSON предназначен для резервной копии.

Для долгосрочного хранения больших объёмов заметок в будущем может потребоваться переход с `localStorage` на IndexedDB. Текущая версия сохраняет совместимость с существующим форматом профиля.

## Запуск

```bash
npm install
npm run dev
```

Production build:

```bash
npm run build
```

Preview:

```bash
npm run preview
```

Tests:

```bash
npm test
```

Тесты покрывают расчётное ядро, регрессии графиков, даты выплат, даты выхода, дополнительные и ночные доплаты, storage migration, заметки, smoke-проверки и motion-маркеры.

## GitHub Pages

Vite использует относительный `base: './'`, поэтому приложение подходит для репозитория вида:

```text
https://username.github.io/WorkerTink/
```

В репозитории есть `.github/workflows/deploy.yml`. Workflow запускается после push в `main`, устанавливает зависимости, выполняет тесты и production build, после чего публикует `dist` через GitHub Pages.

Перед первым deployment в GitHub откройте:

**Settings → Pages → Source → GitHub Actions**.

## Offline / PWA

WorkerTink не требует сервера для хранения профиля. Service Worker кэширует production-ресурсы через `vite-plugin-pwa`, а профиль сохраняется локально.

После обновления версии PWA использует `registerType: 'autoUpdate'` и очищает устаревшие cache entries.

## Ограничения расчётов

WorkerTink — планировщик и расчётный инструмент, а не бухгалтерская система. Зарплата, отпускные и больничные могут зависеть от системы оплаты труда, локальных актов, фактических начислений, региональных условий и действующего законодательства.

Приложение специально показывает модель расчёта, а не выдаёт её за официальный расчёт работодателя.
